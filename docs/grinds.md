# Grinds: examples and instruction parts

Moved word for word from CLAUDE.md (mw-gq6.485). CLAUDE.md keeps the rule every grind story follows: change a grind's behaviour, update or add its examples in the same story.

Each grind (`grinds/<kind>.json`) keeps BDD-style scenarios under `grinds/examples/<kind>/<name>.json`: the request (with `schemaVersion`), the recording beside it where the grind takes one (verse-read), and an `expect` block of simple checks on answer fields. Format: `grinds/examples/README.md`. `mw grist smoke lampas` runs them against the live grist; `tests/unit/grind-examples.test.ts` validates every request against `grinds/<kind>.input.schema.json` and every `expect` path against the answer schema, and fails when a grind has no scenario or no input schema.

The bible-talk and verse-ask instructions are one part per section (mw-skwocd.8): `grinds/bible-talk.instructions/` and `grinds/verse-ask.instructions/` hold `NNN-<section>.md`, the first the `#` title and each other one `##` section (its `###` subsections with it), numbered in tens so name order is the order the model reads them; `grinds/<kind>.json`'s `instructions` names the directory, and the mill reads its `*.md` parts in name order, joined by one blank line. **A story edits only the part of the section it changes.** A new section is a new part numbered between its neighbours (`255-<section>.md`), never a renumbering; each part ends in one newline. Tests read a grind's instructions whole through `scripts/grind-parts.ts` `instructionsOf(kind)`, never by path (`tests/unit/grind-parts.test.ts` fails on a test that reads one by path, and holds the split to the file it came from, byte for byte). The other grinds' instructions are still one file each.

Every grind's instructions stay under 100,000 bytes, as `cat grinds/<kind>.instructions/*.md | wc -c` counts them (mw-5r3p30.728): every ask pays for all of them, and the mill warns past that. `tests/unit/grind-instructions-size.test.ts` fails at 100,000; make room by saying a rule once, not by dropping one (`docs/design/bible-talk-trim-map.md` is how the bible-talk trim did it).
