# The tutor's doors: every in-page tutor button, audited

The Governor's words (2026-11-07, mw-5r3p30.1144): "do we need to ask the tutor if we have the question mark available ... maybe we don't
have to be as long as the question mark it's the context that it needs from the page". The floating ? (`FloatingTutor`, `src/AskTutor.tsx`)
is the tutor's one door (mw-5r3p30.880, .882). This file lists every other in-page tutor entry in `src/`, what it sends, what the ? sends on the
same screen, and the verdict. The rule the audit applies (PROVISIONAL, the Governor to confirm): an in-page button stays only where it hands the
tutor something the ? on that screen does not; a Help *topic* about the tutor is not a door.

How the ? gets its context: a screen calls `useReportScreen({name, facts})` (`src/tutor/screenContext.ts`), and `AskTutor` (the route's door,
`useDoorTarget`) opens the Talk sheet over `{title: name, screen: {name, facts}}` kept under `screen.<name>` (or the `kept` key the screen reports).
It sends **no first question and no `focus`**. A screen that reports no facts sends its name alone (`contextOf`). A sheet or dialog registers its own
target (`useDoorTarget(open, hidden, sheet)`; `DialogAskTutor`). An in-page button instead calls `askTheTutor(first?)` (`src/tutor/askNow.ts`, the same
sheet plus an optional first question and `focus`), or opens the Reader's Talk sheet on a verse (`src/nav/readerRequest.ts`).

`grep -rn "Ask the tutor" src` and the openers `askTheTutor`, `askInReader`, `talkInReader`, `askAboutWord`, `setTalking`/`TalkHost`, `onAsk` give the table.
